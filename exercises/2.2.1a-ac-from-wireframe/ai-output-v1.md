Feature: Add a PayeeScenario 1: Mandatory Field ValidationGiven the user is on the "Add a payee" screen.   When the user leaves the Payee name (*) or LedgerLeaf account number (*) fields blank and clicks Add payee.   Then inline validation errors are triggered, preventing submission until both mandatory fields are populated.   Scenario 2: Non-Existent Account Number Error HandlingGiven the user has entered a valid Payee name.   When the user enters a LedgerLeaf account number that does not exist in the bank's core system and clicks Add payee.   Then an error message is displayed indicating that the account number does not exist.   Scenario 3: Successful Payee Creation with Optional FieldsGiven the user enters a valid Payee name (e.g., Jordan Lee) and an active LedgerLeaf account number (e.g., matching format 100-000).   And optionally provides a Nickname, selects the Payee type from the dropdown (defaulting to Person), and checks Save as favourite.   When the user clicks Add payee.   Then the payee is successfully created, the list counter updates (e.g., incrementing from 3 of 20), and the new payee appears in the Your payees sidebar.   Scenario 4: New Payee Transfer Limit NoticeGiven the user is viewing the Add a payee form.   Then an informational text box with a dotted border is visible stating: "New payees can receive up to $1,000 in the first 24 hours."   Scenario 5: Payee List Capacity & Existing Payees DisplayGiven the user is on the screen.   Then the Your payees section displays the current count out of the maximum limit (3 of 20).   And active payees are listed with their details, including favourite indicators (★ for Sam Saver), account numbers, and a delete action icon per entry.   Scenario 6: Form CancellationGiven the user has entered details into the Add a payee form.   When the user clicks Cancel.   Then the form fields are cleared or the user is redirected away from the add payee view.
